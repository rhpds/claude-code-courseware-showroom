== Key Concepts

Claude Code's agent system lets you spawn subagents -- isolated instances that run a focused task and return their findings to the main conversation. This is the same mechanism used by skills with `agent: true`, but applied specifically to code review.

=== How It Works

. The main conversation spawns a subagent with a specific type
. The subagent runs in its own context window
. It has access to tools (file reading, search, bash, MCP)
. It returns structured findings when done
. The main conversation receives only the results, not the intermediate work -- saving context and cost

=== Built-in Agent Types

**security-reviewer**::
Focus: authentication, injection, secrets, container security, RBAC, dependency vulnerabilities, unsafe deserialization

**patternfly-ui-ux-reviewer**::
Focus: PatternFly component usage, accessibility (WCAG), responsive design, UX patterns, design consistency

**devops-platform-engineer**::
Focus: Dockerfiles, CI/CD pipelines, K8s/OCP manifests, resource limits, deployment strategies, infra-as-code

**container-specialist**::
Focus: container build optimization, runtime debugging, image size, layer caching, registry operations

=== Custom Agents

You can define your own agents by creating markdown files in `.claude/agents/` directories. These extend the built-in set with project-specific or team-specific review capabilities.

Agent definitions are markdown files with frontmatter and instructions:

----
---
name: code-quality-reviewer
description: Reviews code for quality, naming, complexity, and test coverage
---

You are a code quality reviewer. Examine the repository and report on:
1. Naming -- clear and consistent?
2. Complexity -- functions over 50 lines or 4 levels deep?
3. Duplication -- repeated code that could be consolidated?
4. Test coverage -- main paths and edge cases covered?
5. Error handling -- bare except/catch blocks?

Report findings by severity: Critical, Major, Minor.
----

== Multi-Agent Review Patterns

**Direct parallel**::
Spawn 2+ agents at the same time. Each runs independently with its own focus area. You get separate findings from each.

**Team lead pattern**::
A coordinator agent reads changed files, decides which specialists are relevant, and spawns only those. This avoids running agents that have nothing to review.

**Sequential pipeline**::
One agent identifies risk areas, second agent deep-dives into those specific areas. Good for large codebases where you want to focus effort.
